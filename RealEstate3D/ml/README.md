# ML — выбор лучшего места для склада

Модель оценивает каждое здание Саратова (≈ 87 тыс.): насколько его место подходит под склад с учётом
дорожной ситуации — выезд фуры из города, последняя миля до магистрали, жильё и школы рядом,
доступность города, ж/д. Пользователь вводит адрес объявления и получает балл 0–100 с объяснением.

## Как запустить (из папки `ml`)

```text
pip install -r requirements.txt
python src/osm_data.py         # один раз: здания и объекты OSM (уже скачанные не качаются заново)
python src/build_model.py      # признаки → обучение и проверка 4 моделей → баллы → Excel, отчёт (≈ 10–15 мин)
python src/make_map.py         # карта out/map/ и один файл out/Карта складов Саратова.html
python src/make_notebook.py    # ноутбук для Colab и архив out/warehouse_model_colab.zip
```

Быстрая проверка: `python src/build_model.py --fast` (без подбора гиперпараметров) или `--test` (часть города).
Карта: `out/map/Открыть карту складов.cmd` (с подложкой OSM) или двойной щелчок по `out/Карта складов Саратова.html`.

## Структура

| Путь | Что лежит |
|---|---|
| `src/road_data.py` | Загрузка дорожной базы DE в pandas / geopandas |

| `src/osm_data.py` | Здания, промзоны, ж/д, школы, магазины, жилые кварталы из OSM (Overpass, без ключей) |
| `src/features.py` | Признаки здания: выезд, последняя миля, окружение, достижимость города, ж/д и место |
| `src/train_model.py` | Метки A/B, 4 модели, проверка по блокам 3 км, исследование групп признаков, вклад групп |
| `src/scoring.py` | Профили, правила безопасности, тексты «почему подходит / что мешает / предупреждения» |
| `src/build_model.py` | Весь расчёт + `building_report(osm_id или адрес)`, `score_address(адрес)`, `point_report(lat, lon)` |
| `src/reports.py` | `warehouse_sites.xlsx`, `model_report.html/json`, `warehouse_results.sqlite` |
| `src/make_map.py` | Карта (`index.html`) и страница экспертной разметки (`label.html`) |
| `src/import_labels.py` | JSON с оценками экспертов → `labels/expert_labels.xlsx` |
| `config/warehouse_config.json` | Все настройки: α, веса профилей, пороги правил, выезды |
| `notebooks/warehouse_sites.ipynb` | Ноутбук для Colab (собирается `make_notebook.py`) |
| `labels/` | Экспертные оценки (коммитим) |
| `models/`, `data/`, `out/` | Модели, промежуточные данные, результаты — **в git не попадают** |

## Откуда данные

Дорожную базу готовит **дата-инженер** в `../data_engineering/` — она не копируется и открывается только
на чтение (`data_engineering/data/processed/saratov_roads.sqlite`). Если её нет, соберите её
(из папки `data_engineering`): `python scripts/fetch_osm.py`, затем `python scripts/build_data.py`.
Пустое ограничение в базе означает «нет данных», а не «проезд разрешён» (`../data_engineering/ПЕРЕДАЧА_КОМАНДЕ.md`).

## Что ML отдаёт команде

- **Backend:** функция `build_model.building_report(osm_id | адрес)` / `score_address(адрес)` → словарь (JSON)
  с баллом, подбаллами, временем до выездов, причинами и предупреждениями; или таблица
  `wh_building_score` в `out/warehouse_results.sqlite`. Числа совпадают с картой.
- **Frontend:** поля `score` (итог), `reasons` («почему подходит»), `warnings`, `checked_at` (дата расчёта)
  берутся из той же карточки. Формат ответа согласуйте с backend до интеграции.

## Ограничения

Метка модели — где склады стоят **сейчас** (OSM), а не «где лучше всего». Пробки статические, спрос по городу
приближён кластерами жилья и магазинов, нет цен, аренды, свободных участков и санитарных зон.
Экспертная разметка (`label.html` → `import_labels.py`) нужна, чтобы проверить и дообучить модель.
