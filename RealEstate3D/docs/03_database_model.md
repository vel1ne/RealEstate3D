# Как устроена база

SQL — способ читать и менять данные. Одна таблица со всеми улицами не решит задачу: у каждого участка может быть несколько правил, действующих в разное время, а у здания — несколько въездов.

## Готовая локальная база

**data/processed/saratov_roads.sqlite** содержит:

- dataset — происхождение и время снимка;
- road_segment — один OSM way на строку, имя/номер/класс дороги, доступ, грузовые теги и числовые ограничения;
- point_constraint — точки с барьерами/частью габаритных ограничений;
- turn_restriction_raw — исходные отношения запретов поворотов.

Геометрия в SQLite хранится как текст GeoJSON. Это переносимая витрина для просмотра, без PostGIS и готовой маршрутизации. NULL в числовом поле означает неизвестное или неразобранное значение. Исходное значение всегда остаётся в tags_json.

Выгрузка не является полной инвентаризацией дорожных знаков. Точки извлечены по barrier/maxheight/maxweight, а не по всем возможным ключам. Состав и границы запроса сохранены в data/raw/query.overpassql.

## Целевая PostgreSQL + PostGIS

Схема **sql/01_schema_postgis.sql** дополнительно содержит:

| Таблица | Назначение |
|---|---|
| data_source | Источники, URL, лицензии |
| dataset | Снимки данных и происхождение |
| road_segment | OSM-участки с геометрией и тегами |
| point_constraint | Точечные препятствия |
| turn_restriction_raw | Исходные отношения поворотов |
| restriction | Официальные/полевые правила, даты, исключения и проверка |
| property | Объекты недвижимости |
| property_entrance | Реальные въезды, ворота и условия разгрузки |
| vehicle_profile | Параметры сравниваемой машины |
| accessibility_assessment | Результат проверки маршрута к въезду, время и причины |

Ручные ограничения, объекты и оценки сейчас не заполнены вымышленными записями. Три профиля машин — иллюстративные входные параметры, а не юридическая классификация.

## Основные поля дорожной строки

osm_way_id — идентификатор в OSM; name/ref — название/номер; highway — класс; hgv/goods/hgv_articulated — исходные виды доступа; maxweight_t — фактическая полная масса; maxweightrating_t — разрешённая максимальная масса; maxaxleload_t — нагрузка на ось; maxheight_m/maxwidth_m/maxlength_m — габариты; oneway — направление; surface — покрытие; tags — полный набор исходных тегов; geom — линия WGS84.

Числовые колонки извлекаются консервативно: только положительное число без указания других единиц. Например, значение в футах или pounds не преобразуется молча. Ограничения maxweight:hgv и другие специальные варианты остаются в tags и требуют отдельной нормализации; карта учитывает простые числовые варианты с суффиксом :hgv.

## Перед маршрутизацией

OSM way не равен ребру маршрутного графа. Его нужно делить по настоящим узлам пересечений, сохранять родительский OSM ID, учитывать направление, мосты/тоннели, barrier-узлы, запреты поворота, временные правила и исключения. Затем можно выбрать и проверить движок маршрутизации. Наличие GeoJSON или пространственного индекса не делает маршруты автоматически грузовыми.

Результат «проезд подтверждён» разрешён только после проверки непрерывного маршрута и самого въезда с учётом параметров машины и времени. Расстояние по прямой до ближайшей дороги не годится для такого вывода.
