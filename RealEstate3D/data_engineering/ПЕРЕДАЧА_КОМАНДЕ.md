# Передача команде: дороги Саратова и грузовая доступность

Версия комплекта: исследовательский прототип, 27 октября 2026 года.

**Передавать можно для знакомства с данными, проектирования и начала интеграции. Комплект пока не является готовым сервисом грузовой маршрутизации или обучающим набором с подтверждёнными ответами о проезде.**

## Что реально готово

| Часть | Состояние |
|---|---|
| Локальная карта | Рабочий прототип: поиск, слои, параметры машины, карточки на русском, исходные коды в сворачиваемом разделе |
| SQLite | Созданная и заполненная база, а не только SQL-текст; целостность и внешние ключи проверены |
| GeoJSON | Геометрия участков и точечных препятствий для географической обработки |
| PostgreSQL + PostGIS | Подготовлены схема и импорт реального снимка; на PostgreSQL пока не выполнялись |
| Серверный API платформы | Не реализован; serve_map.py только открывает локальную карту |
| Грузовая маршрутизация | Не реализована; направленный граф и вычисление допустимого пути отсутствуют |
| Проверенный реестр ограничений | Не собран; имеются наблюдения OSM и перечень официальных источников для дальнейшей проверки |
| Обучающая разметка ML | Не собрана; подтверждённых целевых меток «можно/нельзя проехать» нет |
| 3D-реконструкция | Не реализована; набора фото/видео помещений в комплекте нет |

## Для разработчика бэкенда

Начните с data/processed/saratov_roads.sqlite, sql/04_queries_sqlite.sql и ../docs/03_database_model.md. В SQLite есть четыре таблицы:

- dataset — происхождение снимка;
- road_segment — 39 796 OSM-линий с атрибутами и геометрией;
- point_constraint — 2 301 точка с барьерами или выбранными ограничениями;
- turn_restriction_raw — 546 исходных отношений ограничений поворота.

Геометрия в SQLite — текст GeoJSON, а не тип PostGIS. Для целевой базы сначала разверните отдельную тестовую PostgreSQL-базу с PostGIS, затем выполните 01_schema_postgis.sql и 02_import_roads_postgis.sql. Проверьте числа строк и запросы 03_queries_postgis.sql.

Начальный импорт рассчитан на один исследовательский снимок: он помечает предыдущие дорожные строки как неактуальные и заменяет кеши точек/поворотов. Не запускайте его в общей рабочей базе нескольких регионов без адаптации. Для эксплуатации нужны миграции, стратегия обновлений, резервное копирование, авторизация и API, а также модель связи недвижимости с реальными въездами.

Таблица road_segment содержит один OSM way на строку. Это ещё не ребро маршрутного графа: нужны разбиение по действительным пересечениям, направления, запреты поворота, точки препятствий, уровни мостов/тоннелей, условия по времени и исключения. Таблицы недвижимости, въездов, проверенных ограничений и оценок в схеме PostGIS пока пусты; три профиля машин демонстрационные.

## Для специалиста по машинному обучению

Комплект подходит для анализа покрытия данных, исследования признаков, проверки качества и прототипирования. **Пока он не подходит как готовый набор для обучения модели, которая достоверно определяет возможность проезда фуры.**

Причины: нет подтверждённых ответов по конкретным машинам/маршрутам/датам; данные об ограничениях заполнены редко; нет фактических поездок и замеров подъездов. Отдельный hgv-тег присутствует у 71 из 39 796 дорожных линий, примерно 0,18%. Другие ограничения встречаются в общих ключах и точках; отсутствие hgv не означает отсутствие всех данных.

Не заменяйте отсутствие hgv или maxweight разрешением проезда, нулевым ограничением или достоверным отрицательным классом. Цвета карты вычислены из тех же исходных тегов и параметров машины — это не независимая разметка для обучения и оценки качества модели.

Сначала согласуйте задачу: прогноз времени пути, поиск вероятно неполных данных, оценка качества подъезда или другая измеримая цель. Соберите целевые метки с источником, датой, профилем машины и геометрией маршрута. При подготовке обучающей и проверочной выборок учитывайте соседние участки одной дороги, связанные объекты и время снимков, чтобы не оценивать модель на почти тех же данных, на которых она обучалась.

Разрешённость движения задаётся дорожными правилами и параметрами машины; соответствующий расчёт требует графа и проверенных ограничений. Предположение модели не должно автоматически превращаться в подтверждённое право проезда.

Для команды, занимающейся **3D по фото/видео**, эта дорожная база даёт географический контекст объекта. Для их основной задачи понадобятся отдельные материалы съёмки, требования к ракурсам/покрытию, масштабу и оценке результата.

## Договорённости о данных

- Ключ дороги — osm_way_id; одна улица обычно представлена несколькими строками.
- Геометрия: WGS84, EPSG:4326; координаты GeoJSON идут в порядке долгота, широта.
- Область запроса: 45.70–46.35 по долготе, 51.35–51.82 по широте. Это Саратов и окрестности, а не административная граница; целые линии могут выходить за рамку.
- Масса — тонны; габариты — метры. maxweight означает фактическую полную массу, maxweightrating — разрешённую максимальную массу. Грузоподъёмность не равна полной массе.
- NULL — значение отсутствует или не разобрано; исходные строки сохранены в tags_json (SQLite) / tags (PostgreSQL).
- Числовые колонки извлекают простые числа в стандартных единицах; особые единицы, условия и суффиксы нужно дополнительно нормализовать. Например, специальное maxweight:hgv остаётся в исходных тегах.
- Состояние: снимок, а не поток оперативных дорожных событий. Время базы OSM: 2026-10-27T18:23:02Z.
- Перевод выполнен в интерфейсе; английские идентификаторы и значения исходных данных не изменялись.

## Критерии следующей готовности

Для пилота: импорт проверен на реальном PostGIS; выбранные объекты имеют подтверждённые точки въезда; актуальные ограничения и исключения нанесены на участки; допустимый непрерывный маршрут проверен хотя бы для двух реальных профилей машин; сервер возвращает результат с причинами, источниками и датой проверки. Недостаток данных должен давать «неизвестно».

Для обучения ML: согласованы задача и целевая переменная; получены независимые проверенные метки; подготовлены корректные выборки и критерий качества. На текущем этапе обещать качество модели нечем.
