# Data Engineering — дорожные данные и грузовая доступность

Первый модуль платформы: дорожные данные Саратова и окрестностей. Начальный набор подготовлен 27 октября 2026 года.

Для передачи разработчикам бэкенда и машинного обучения начните с **ПЕРЕДАЧА_КОМАНДЕ.md**. В нём описано, что уже готово, что проверено и какие части ещё предстоит реализовать.

## Первый запуск: данные не хранятся в git

Большие сгенерированные файлы (снимок OSM, SQLite, GeoJSON, HTML-карта, SQL-импорт — около 180 МБ) исключены из репозитория через `.gitignore`. После клонирования соберите их сами (команды выполняются из папки `data_engineering`):

```text
python scripts/fetch_osm.py
python scripts/build_data.py
```

## С чего начать

1. Откройте **Открыть карту.cmd** двойным щелчком. Карта откроется в браузере. Оставьте окно запуска открытым, пока пользуетесь картой. Онлайн-фон OSM можно включить в разделе «Слои»; для него нужен интернет. Если сервис откажет в доступе, фон отключится и появится пояснение, а дороги и поиск останутся доступны.
2. Для просмотра заполненной SQL-базы откройте **data/processed/saratov_roads.sqlite** в клиенте SQLite. Примеры запросов: **sql/04_queries_sqlite.sql**.
3. Для базы платформы создайте отдельную PostgreSQL-базу с установленным PostGIS и последовательно выполните **sql/01_schema_postgis.sql**, **sql/02_import_roads_postgis.sql**, **sql/03_queries_postgis.sql**.
4. Прочитайте **../docs/01_scope_and_roadmap.md**: там границы готовности, этапы проверки и дополнительные идеи для объявления.

SQL — язык запросов. База SQLite — готовый локальный файл для знакомства с данными; PostgreSQL + PostGIS — целевая база многопользовательской платформы. Excel удобен для ручного просмотра небольших выгрузок, но пространственные запросы и обновляемые связи лучше вести в базе.

## Что находится в папке

| Путь | Содержимое |
|---|---|
| docs/ | Источники ограничений, отчёт проверки, заметки по карте (общие документы — в ../docs) |
| maps/ | Локальная интерактивная карта и её библиотеки |
| data/raw/ | Неизменённый снимок OSM и запрос выгрузки |
| data/processed/ | Заполненная SQLite-база, GeoJSON, отчёт качества |
| sql/ | Схема PostGIS, загрузка реальных данных и запросы |
| scripts/ | Воспроизводимое преобразование данных и шаблон карты |

## Важные границы готовности

- Данные настоящие, получены из OpenStreetMap через Overpass; количественные показатели и время базы находятся в **data/processed/quality_report.json**.
- Это снимок участков и наблюдений, а не проверенный перечень разрешённых для фур дорог. Наличие дороги не означает разрешение грузового проезда. Отсутствие тега не означает отсутствие ограничения.
- «Магистрали» в карте — классы OSM motorway/trunk/primary, а не измеренные основные маршруты фур. Подтверждение грузового потока — отдельная задача с перевозчиками/телематикой.
- Отдельно сохранены точечные препятствия и отношения запретов поворота. Маршрутный граф пока не построен; карта не вычисляет непрерывный допустимый маршрут к объекту.
- Правила с временем, направлениями, условиями и исключениями требуют отдельного разбора. Старые сообщения органов власти не объявлены текущими ограничениями.
- PostgreSQL-сервер не развёрнут; схема и импорт подготовлены, но на действующем PostgreSQL не выполнялись. Локальная SQLite-база создана и проверена.
- 3D-реконструкция помещения не реализована. По произвольному одному фото точную полную модель обещать нельзя: потребуются требования к съёмке, масштабу и проверке результата.

## Обновление

Для повторной загрузки запустите scripts/fetch_osm.py: он использует сохранённый запрос data/raw/query.overpassql и сохраняет предыдущий сырой снимок в data/backups. Затем запустите:

```text
python scripts/build_data.py
```

Скрипт пересобирает локальную SQLite-витрину, GeoJSON, HTML-карту и SQL-импорт. Ручные правки в сгенерированных файлах при этом заменяются. В PostgreSQL повторный импорт обновляет снимок OSM; таблица ручных/официальных restriction не очищается. Схема — начальная; дальнейшие изменения оформляйте миграциями.

## Запуск карты

Сохраняйте папку data_engineering целиком, чтобы ссылки на assets работали. Для запуска используйте **Открыть карту.cmd**. При прямом открытии maps/saratov_trucks.html дорожный слой работает офлайн, а онлайн-фон отключён: локальный файл не передаёт обычный адрес страницы серверу подложки.
